The Model Gateway

Phase 0 ended with every SDK mechanic understood and every boundary checked — yet exercise 04's client still imports the SDK's types, catches the SDK's exceptions, and speaks the wire's vocabulary in the same file that keeps the ledger. Phase 1 opens with the main question: where exactly does the line between the SDK's mechanics and Hermes's policy go — and who owns the types on each side of it?

Why this matters for Hermes Scenario step S4 is this lesson verbatim: model calls go through the ModelGateway — below the port: the client SDK's mechanics; above it: Hermes policy — routing, provider, model choice — and failures arrive as typed errors the supervisor can classify. The port you build today also seeds S6 (the supervisor's AbortSignal crosses it) and S7 (the requestId it keeps is the trace's first field). Two spine threads advance: the six responsibilities all move below the line without changing, and the boundary rule's parse (lesson 0005) finds its permanent home inside the adapter. The still-open provider-neutrality decision lands here. Phase 1 opens.

1 · The client you would have to copy

Open exercise 02's client.ts and read it as the Phase 1 supervisor would: one file that imports Anthropic, constructs it with endpoint and key, catches RateLimitError / APIUserAbortError / APIError in a chain, and reads message.usage into a ledger. Now imagine the loop of lessons 0008–0011 built the same way — every file that wants a model call repeats the imports, the catch chain, and (since lesson 0005) the boundary parse. Three costs, all measured in this lab:

  • Failure is an exception, everywhere. A 429 unwinds the caller's stack unless every caller writes the same instanceof chain. Lesson 0005 §3 already named what a supervisor wants instead: an expected outcome to classify, riding as data.
  • Tests need a server. The mock is a faithful double, but it is a process — a port to hold, a stale instance to hunt (it has bitten three sessions running). The loop's policy — "on throttle, park and retry later" — deserves a test that runs in a millisecond with no wire at all.
  • The SDK's vocabulary is load-bearing. Domain code that types its variables as Anthropic.Message and switches on "end_turn" re-couples to the provider at every call site. An SDK upgrade — or a provider decision — becomes a domain rewrite.

The fix is one deliberate seam. Before building it, account for the layers — a claim that "the gateway changes everything" has to say which everything:

New today vs. reprise. Genuinely new ideas — five: ⑴ a port is an interface the caller owns — dependency inversion turns the import arrow around; ⑵ an adapter translates three currencies (calls down, replies up, exceptions into data) and is the boundary parse's permanent home; ⑶ at the port, every outcome of a call is a value — exceptions stop below the line; ⑷ a fake is a real, in-process implementation of the port — a different altitude of test double than the wire mock; ⑸ provider neutrality is a property of the seam, not a count of adapters — today's decision. Everything else is reprise: the six responsibilities (0001–0003, unmoved), typed error classes (0003), the abort signal (0004), safeParse and rejection-as-data (0005), narrowing a discriminated union (0001/0004/0005), the mock as test double and the base-URL seam (0002).

2 · The port: an interface the domain owns

Version pin. Everything below was verified against @anthropic-ai/sdk 0.113.0 and zod 4.4.3 exactly (no ^/~ in any claim), by live runs against the exercise 01 mock. All numbers in this lesson are those measurements.

You have met this seam before, one level down. Lesson 0002's base-URL seam swapped the real API for the mock at the wire — a configuration value chose where the bytes went, and no code changed. The port is the same move lifted to the type level: an interface chooses which implementation runs, and no domain code changes. One word, two prior meanings — pin them before they collide:

The phraseWhat it namesWhere you met it
port 8787a TCP address — where a process listens for bytesthe mock, since exercise 01 (and the PORT env override)
the port in ports-and-adaptersan interface the domain owns — where implementations plug intoday: gateway.ts, the seam this whole lesson builds

Read the port's file the way lesson 0003 read the SDK's entry point — declaration first, and honest about what survives compilation (hermes-sdk-lab/05-model-gateway/src/gateway.ts, abridged):

export interface ModelCall  { prompt: string; maxTokens: number }
export interface ModelReply { text: string; stop: StopCause;
                              usage: { inputTokens: number; outputTokens: number };
                              requestId: string | null }

export type GatewayResult =                       // narrow on `ok` — lesson 0005's move
  | { ok: true;  reply: ModelReply }
  | { ok: false; failure: GatewayFailure };

export interface ModelGateway {
  complete(call: ModelCall, options?: { signal?: AbortSignal }): Promise<GatewayResult>;
}
SyntaxMeaningWhat exists at runtime?
interface ModelGatewaya contract declaration in the domain's vocabularynothing — erased, like every interface since lesson 0001. Contrast lesson 0005's z: a schema is a runtime value; a port is not
implements ModelGatewaya compile-time claim on a class, checked structurallynothing of the claim — but the class survives as a real constructor
new AnthropicModelGateway(client, model)construct one adapter, configured from outsidean object holding the SDK client — mechanics, packaged
gateway.complete(call)invoke through the port's signaturewhichever implementation the wiring chose does its runtime work
options?.signalthe supervisor's kill switch crosses the porta real AbortSignal — allowed across because it is a web platform standard, not an SDK type

The standing distinction, fourth lesson running, with a twist: a signature tells TypeScript what may be called; the implementation does the runtime work. Today one signature has two implementations — AnthropicModelGateway and FakeModelGateway — and the domain cannot tell which one it holds, because all it ever imported was the signature. That ignorance is the product. And since the interface is erased, ask what enforces the seam at all: the type-checker at every implements and every import, at build time. A port is not a runtime guard — it is discipline made checkable. The runtime guard is a different artifact, and it lives in §3.

Beside the declaration, the two runtime values Part A and Part B1 actually produced — one per arm:

// Part A — the proof arm                  // Part B1 — the refusal arm
{                                          {
  ok: true,                                  ok: false,
  reply: {                                   failure: {
    text: "Hello from the mock. These bytes…",              kind: "throttled",
    stop: "completed",                         retryAfterMs: 5000,
    usage: { inputTokens: 11,                },
             outputTokens: 42 },           }
    requestId: "req_mock_0001",            // the wire said `retry-after: 5` (seconds);
  },                                       // the port speaks milliseconds — translation,
}                                          // not passthrough

Note what the vocabulary did: end_turn became completed, input_tokens became inputTokens, an exception became { kind: "throttled" }. None of this is cosmetic. Every word in gateway.ts is one Hermes chose, so no provider spelling is load-bearing above the line — that single fact is what §4's decision stands on.

3 · The adapter: three translations, zero new bytes

First, the wire truth, because an architecture lesson can hide a wire lie: during Part A the mock's terminal shows exactly the exchange exercise 02 produced —

POST /v1/messages  (req_mock_0001)
x-api-key: … · anthropic-version: 2023-06-01 · content-type: application/json
{ "model": "claude-opus-4-8", "max_tokens": 100, "messages": [ … ] }

HTTP/1.1 200 OK · request-id: req_mock_0001 · stop_reason=end_turn input_tokens=11

The port added nothing to this. No header, no envelope, no proxy hop. A gateway is compile-time architecture; the network cannot see it. What changed is who gets to speak which language — the adapter (anthropic-gateway.ts, the file where the SDK import lives) performs three translations:

  1. The call, downward. ModelCall → the SDK's params object. The model id is not hardcoded here: routing is policy (S4), so the id enters the adapter as constructor configuration, decided above.
  2. The reply, upward — through the boundary parse. The SDK returns a value typed as Message; lesson 0005 established at length that this is an erased claim, not a check. So the adapter runs WireReplySchema.safeParse on it — a schema deliberately narrower than Message, covering exactly what ModelReply consumes (text, stop word, the ledger's two numbers; stop_reason non-nullable, because null belongs to lesson 0004's streaming skeleton and a finished reply must commit). The parse you installed at the client's edge last lesson has found its permanent address: inside the adapter, below the port, run once for every reply forever.
  3. The failures, upward — from classes to data. Exercise 02's catch chain (instanceof RateLimitError → APIUserAbortError → APIConnectionError → APIError) is written one final time, in one place, and its output is no longer control flow but a value: GatewayFailure. Note the asymmetry with the port: SDK error classes are runtime values (that is why instanceof works on them — lesson 0003), while the port's interfaces are erased. The adapter spends the runtime artifact to produce data; anything it cannot recognize is a bug in our own process and is rethrown — classifying bugs as gateway failures would hide them.

Part B, measured — three failures crossing the port as data, no try/catch anywhere above it:

B1 throttled → { outcome: 'retry_later', tokensSpent: 0,
                 notes: ['provider asked for 5000 ms of backoff'] }
B2 aborted   → { outcome: 'gave_up',     tokensSpent: 0, notes: ['aborted by the operator'] }
B3 malformed → { outcome: 'gave_up',     tokensSpent: 0, notes: [
                 'reply refused at the boundary',
                 'stop_reason: [invalid_value] Invalid option: expected one of …',
                 'usage.output_tokens: [invalid_type] Invalid input: expected number, received string' ] }

B3 deserves a slow look. These are exercise 04's exact drifted bytes — the ones whose ledger printed "1142" against a real spend of 53. Through the gateway, the same bytes never reach a ledger at all: the adapter refuses them with both issues attached, and the supervisor books zero tokens and gives up loudly. You argued for precisely this in your lesson-0005 recall: a plausible silent error is more dangerous than a conspicuous false alarm — which is why the gateway validates usage at the boundary instead of trusting arithmetic on wire values. That argument is now load-bearing code.

4 · The fake, and the decision that was waiting for it

"Mechanics below, policy above" needs its deconfusion before the fake makes sense: below does not mean hidden, private, or wrapped in secrecy — the adapter imports the SDK in plain sight, and main.ts constructs the client openly. Below/above describe the import graph, nothing else: files above the port may not name the SDK; files below may not be named by the domain. And "the port has two implementations" does not mean two providers — the second implementation is a test artifact:

exercise 01's mock serverFakeModelGateway
doubles the API at…the wire — real HTTP, port 8787the port — a method call, in-process
exists asa separate process you start, stop, and (three sessions running) hunt when stalean object your test constructs in the line above the assertion
what it exercisesthe six responsibilities, the SDK's transport, the parse — mechanicsthe supervisor's decisions — policy, with mechanics assumed correct
speed, measured~400 ms per call (deliberate latency)0.6 ms for a whole two-call scenario, mock stopped
keeps living becauseadapter changes need a wire to prove againstthe loop's tests must not need a network — Phase 1's exit criterion

Part C is the demonstration: stop the mock — actually stop it — and run the same supervisor against a fake scripted in the port's vocabulary. Measured: the landed report is byte-identical to Part A's except request: (none); the scripted throttle drives the same retry_later branch B1 drove over the wire; and fake.calls hands the test a record of what the domain actually asked. Policy became testable at memory speed because policy's only dependency is a signature.

Which brings the open decision due since session 1 — provider neutrality vs. Claude-only — to the only place it could land. Decided: a provider-neutral port, exactly one live adapter.

  • The port is neutral by construction, not by ambition. Look at what §2's vocabulary actually names: text, a stop cause, two usage numbers, a failure taxonomy. Nothing Anthropic-shaped crossed the line — not because we abstracted hard, but because the loop's needs (S4–S6) simply do not include provider concepts. Neutrality costs nothing when the interface is derived from the caller's needs instead of the callee's shape.
  • A second live adapter is not built. No mission requirement names a second provider, and no Phase 4 benchmark exists to justify one — building it now would be exactly the speculative work MISSION rules out. Provider choice is policy: when it arrives, it arrives as data above the port (a routing decision constructing a different adapter), not as a rewrite.
  • The honest-port risk is real, and the fake answers it. A port designed against one provider can quietly grow that provider's shape. The classic mitigation is a second implementation — and we have one from day one. Every time FakeModelGateway implements the contract trivially, it re-proves that nothing in the signature requires Anthropic. The fake is the second implementation, for free — a test double, not a second provider, and not proof of interoperability with any real one.

5 · The exercise

Commands and the full measured table live in hermes-sdk-lab/05-model-gateway/README.md; the arc:

  1. Read the files in dependency order — gateway.ts, supervisor.ts, then anthropic-gateway.ts. At each import line, say which side of the port you are on before reading further.
  2. Part A is given — run it and watch both terminals. The supervisor's report on one side; on the other, the proof that the wire never heard of your architecture.
  3. Part B — implement classifyFailure. Run pnpm job b first and watch a raw RateLimitError crash the job — an exception crossing the port is the "before" photo. Then write the instanceof chain (exercise 02's client is your reference), most specific first, rethrowing what you cannot classify. Re-run: three failures, three classifications, zero crashes.
  4. Part C — implement FakeModelGateway.complete, then stop the mock. Ctrl+C in the mock's terminal is part of the exercise. Script a landed reply and a throttle, run pnpm job c, and compare C2's report with B1's — same branch, no wire.
  5. Close the loop: run grep -r "@anthropic-ai/sdk" src/ and account for every hit. Two files, both below the port or in the wiring — that grep is the architecture, checkable in one command.

8 · Say it in your own words

After the lab work, close the loop with your teacher. In the chat, answer these four — no notes, no scrolling up:

  1. Define port and adapter in one sentence each. Then: which of the two survives compilation, and what enforces the one that does not?
  2. Trace a 429 from the wire to the supervisor: bytes → SDK → adapter → port → policy. Name what the SDK hands the adapter, and what the adapter hands the port. Why does instanceof RateLimitError work at runtime when instanceof ModelGateway is not even writable?
  3. A reviewer objects: "the SDK already types the reply — the adapter's safeParse is redundant." Defend the parse in two sentences, citing what the installed .d.ts actually promises and what it cannot promise.
  4. State the provider-neutrality decision as landed, with the strongest argument for it — and name the risk a one-adapter port runs, plus the thing in this exercise that mitigates that risk from day one.

And the compression — if you keep only five sentences from Phase 1's opening: ⑴ A port is an interface the domain owns; both adapters and domain depend on it, so the SDK's types stop below the line while the wire stays byte-for-byte unchanged. ⑵ The adapter translates three currencies — calls down, replies up through the boundary parse, exceptions into failure data — and is the parse's permanent home. ⑶ Above the port, every outcome of a model call is a value the supervisor classifies with a switch; nothing unwinds its stack. ⑷ A fake is a real in-process implementation of the port, which is why the loop's policy is testable in a millisecond with no server at all. ⑸ Provider neutrality landed as a property of the seam — Hermes-owned vocabulary, one live adapter, the fake keeping the contract honest.
