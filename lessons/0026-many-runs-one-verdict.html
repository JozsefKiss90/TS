Many Runs, One Verdict

One passing run shows that the loop can work. How many runs show that it does work, and how do you replay the one that failed?

Why this matters for Hermes S9 (score the run) learns to repeat a task. It continues the course rule that every JSON boundary gets a runtime check: the new task file field is parsed before any run. The win: 4,000 trials at a failure rate the task file sets. The pass rate settles, and a failed trial runs again from its seed.

1 · One run is one sample

A trial is one graded run of one task. Lesson 0025 ran one trial per task. Lab 07's fake replays one script, so a second trial would repeat the first, reply for reply.

A live model varies. It may quote the tool's numbers nine times and drop them the tenth. One trial cannot see that. Many trials of a fake that never varies cannot see it either.

A seeded fake is a fake gateway that replays one of several recordings. A seed number picks the recording, the same one for the same seed.

The task file now accepts a list of recordings with weights. A weight is the recording's share of the trials. So the failure rate is written down before anything runs.

// fixture: string | Variant[]             // tasks/trials.json, task "audit":
type Variant = {                          "fixture": [
  recording: string;                        { "recording": "…/audit-atlas.jsonl",  "weight": 9 },
  weight: number;   // whole, 1 or more     { "recording": "…/parked-audit.jsonl", "weight": 1 }
};                                        ]

The parked recording is lab 12's audit from lesson 0019. Its answer is "Audit complete.", and it leaves out the tool's numbers. So a trial that replays it fails reports_tool_output and nothing else. The true pass rate is 90%.

The parse refuses a weight of zero and a list of one recording. Lesson 0025's file, where every fixture is one path, still passes the same parse.

SeededFakeGateway implements lab 07's ModelGateway port. The loop cannot tell it from lab 07's fake, or from the real adapter.

// 16-benchmark/src/seeded-gateway.ts
import { SeededFakeGateway } from "./seeded-gateway.js";
const gateway = new SeededFakeGateway(variants, 4);   // construct: the seed picks now
gateway.variant;                                      // "…/parked-audit.jsonl"
await gateway.complete(call);                         // replays that recording's next reply

There is one constructor and no overload. A signature tells TypeScript what may be called. The implementation does the runtime work. Math.random takes no seed, so the lab uses a seeded generator called mulberry32.

New today. Five ideas are new.

  • A trial result is a sample, and a seeded fake makes the variation chosen.
  • A weight in the task file sets the failure rate before the run.
  • The pass rate says how often a task passes.
  • pass^k says how likely k trials in a row all pass.
  • A seed reruns a failed trial, so the failure can be read.

2 · Two numbers from n trials

The pass rate is the number of passed trials divided by the number of trials run. It says how often the task passes.

pass^k is the chance that k trials of one task all pass. It says whether the task can be trusted k times in a row.

The τ-bench paper estimates pass^k from n trials, of which c passed, as C(c, k) / C(n, k). C is "n choose k". At k = 1 the estimate equals the pass rate. At n = k it is 1 when every trial passed and 0 otherwise.

// 16-benchmark/src/trials.ts, abridged: the checks on c are left out
export function passHatK(n: number, c: number, k: number): number {
  if (k < 1 || k > n) throw new Error(`k must be between 1 and n (${n}), got ${k}`);
  return c < k ? 0 : choose(c, k) / choose(n, k);
}
TermThe question it answersaudit, 19 of 20 passed, k = 4
pass ratehow often does one trial pass?0.950

pass@kdoes at least one of k trials pass?1.000, because one failure cannot fill four draws

pass@k suits a task where a person keeps the best of several tries. Hermes runs jobs unattended, so a job that fails one time in ten fails often. pass^k shows that cost.

3 · When does the verdict stop moving?

The lab ran audit in ten series of 400 trials, each series on its own seeds. The true pass rate is 90%, because the weights say so.

Measured, ten seriesLowestHighest
pass rate after 10 trials70.0%100.0%
pass rate after 100 trials87.0%95.0%
trials until the rate stays within 10 points of 90%135
trials until the rate stays within 5 points of 90%7106

After ten trials, one series read 70% and five read 100%. The same loop and the same recordings produced every one of those rates. A ten-trial verdict on a 90% task can say "perfect".

Across all 4,000 trials, 3,614 passed, which is 90.3%. pass^k fell as k grew.

kMeasured pass^k0.9 to the power k
10.9030.900
20.8160.810
40.6660.656
80.4440.430

A task that passes nine times in ten passes eight in a row less than half the time. The pass rate hides that. pass^k shows it.

The Hermes OS README says a promotion needs at least ten consecutive clean runs and a signed ADR. That rule asks a pass^10 question, not a pass rate question.

4 · A failed trial runs again

At n = 20, seed 4 fails. The scorecard row names the seed, the recording and the failed grader. pnpm trials --rerun audit --seed 4 runs that one trial again.

5 · The exercise

Commands and measured outputs live in 16-benchmark/README.md.

  1. Run pnpm trials. Write down the audit pass rate and pass^4.
  2. Compute C(19, 4) / C(20, 4) by hand. Compare it with pass^4.
  3. Run pnpm trials --n 4 --k 4. Explain why pass^4 is 0.
  4. Run pnpm trials --rerun audit --seed 4. Open its trace and find the answer line.
  5. Change the audit weights to 3 and 1. Predict pass^4 at n = 20, then run it.
  6. Run pnpm trials --settle. Find the series that settles last.

8 · Say it in your own words

Answer in the chat after the lab, with no notes.

  1. Say why one trial cannot show that a task is reliable.
  2. Say what pass^k answers that the pass rate does not.
  3. Say how you replay a failed trial, and what must stay fixed.

If you keep only four sentences from this lesson, keep these. A trial is one graded run, and one trial is one sample. A seeded fake picks a recording by seed, so the failure rate is chosen and written down. The pass rate says how often a task passes, and pass^k says whether k runs all pass. A failed trial's seed reruns it exactly.
