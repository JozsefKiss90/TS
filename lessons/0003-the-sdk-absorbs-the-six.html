The SDK Absorbs the Six

Exercise 01's raw client, rewritten with the official @anthropic-ai/sdk — pointed at the very same mock. Every responsibility you built by hand is still there; your job today is to find where each one went.

Why this matters for Hermes Phase 1's AnthropicModelGateway will wrap exactly this SDK — so what the gateway must add is precisely what the SDK does not do. Today you map that boundary from below: the SDK gives you mechanics (retries, typed errors, cancellation plumbing) but no policy (budgets, approval, runtime validation of responses). This is also the sequence discipline in action: ordinary model-client SDK now, Agent SDK not until Phase 5 — because after today, neither is magic.

1 · Nothing changes on the wire

Start the mock, send the SDK request, and watch the server's terminal: the same POST /v1/messages, passing the same gates ②③④, answered with the same canned fixture. The mock cannot tell exercise 02 from exercise 01 — an SDK does an API's chores; it does not change the API. Here is where each chore moved:

Exercise 01 — you wrote…Exercise 02 — it became…
① endpointfetch(`${BASE_URL}/v1/messages`)the baseURL option; the path lives inside client.messages.create
② auth"x-api-key": API_KEYthe apiKey option, defaulting to ANTHROPIC_API_KEY from the environment
③ version"anthropic-version": "2023-06-01"nothing — sent automatically, pinned by the SDK release
④ contracthand-built body + JSON.stringify, hand-written interface + astyped MessageCreateParams in, typed Message out (still an assertion — §3)
⑤ errorsif (!res.ok) + hand-parsed envelopetyped error classes, plus automatic retry that honors retry-after
⑥ cancellationsignal in the fetch options{ signal } in the per-request options — plus a retried timeout

2 · Construction is configuration

The raw client scattered the six across a function. The SDK gathers the durable ones into a long-lived client object — construction is configuration; calls are use:

const client = new Anthropic({
  baseURL: "http://localhost:8787", // ① the seam (default: ANTHROPIC_BASE_URL, else api.anthropic.com)
  apiKey: "mock-key",               // ② (default: ANTHROPIC_API_KEY from the environment)
  maxRetries: 2,                    // ⑤ the default — 429s and 5xx retried, retry-after honored
  timeout: 600_000,                 // ⑥ the default — MILLISECONDS in this SDK
});

Anything set here is a default; any single call can override it through the options bag — a second argument that is not part of the request body. Params say what you're asking; options say how this one call should behave on the wire:

await client.messages.create(
  { model, max_tokens, messages },                              // params — the ④ contract
  { headers: { "x-mock-scenario": "rate-limit" },               // options — this call only
    maxRetries: 0, timeout: 200, signal: controller.signal },
);

Where do these claims come from? Not this lesson's word for it: the constructor's JSDoc in node_modules/@anthropic-ai/sdk/client.d.ts states every default (env var fallbacks, 10-minute timeout, maxRetries: 2), and core/error.d.ts lists the whole error family. Those generated declaration files are the SDK's real contract — reading them is a Phase 0 skill, and today's exercise makes you do it once on purpose.

3 · What moved to compile time — and what could not

In exercise 01 you misspelled messages and learned about it from a 400. Today the same typo never reaches a running process:

error TS2769: Object literal may only specify known properties, but 'mesages'
does not exist in type 'MessageCreateParamsNonStreaming'.
Did you mean to write 'messages'?

Deleting max_tokens fails the same way (Property 'max_tokens' is missing). Two of the mock's 400 gates just moved into tsc. But be precise about the limits — three things deliberately did not move:

  • The model id. claude-opsu-4-8 compiles. Peek at the type: Model = 'claude-opus-4-8' | … | (string & {}) — a union of known ids with an escape hatch admitting any string, so new models don't break old SDKs. Types check shape; the model catalog is server-side truth.
  • The key's value. apiKey: "definitely-not-real" sails through mock and compiler alike — lesson 0002's presence-vs-authenticity line, unmoved.
  • The response. The SDK's Message type is attached to JSON.parse output by assertion — exactly the pipeline lesson 0001 §3 dissected, just written by a code generator instead of by you. Nothing at runtime checks that the bytes match. The SDK trusts its server; Hermes will not extend that trust to model-generated data — that runtime-validation gap is precisely what Zod fills at Phase 1's JSON boundaries.

4 · The exercise

Commands and the full experiment table live in hermes-sdk-lab/02-model-client-sdk/README.md; the arc is:

  1. Read the contract first. Open node_modules/@anthropic-ai/sdk/client.d.ts, find the constructor, and read the JSDoc defaults for apiKey, baseURL, timeout, maxRetries.
  2. Break it before you build it. With the TODOs still empty, write the create call with mesages, run pnpm typecheck, and read the error slowly. Fix; delete max_tokens; read again. Undo.
  3. Send it. Terminal 1 pnpm mock, terminal 2 pnpm request. On the 200, print the same four things as exercise 01 (_request_id, stop_reason, first text block, usage) and diff the two clients' output — and the two source files' length.
  4. Run the ⑤/⑥ experiments. The rate-limit header with and without maxRetries: 0; the 200 ms timeout against the mock's 400 ms latency; the 100 ms abort. Watch both terminals every run — count the requests the mock logs.
  5. Close the loop: for each failure you produced, name the layer that caught it — compiler, SDK, mock — and what only the real API could have caught.
