The SDK Absorbs the Six Responsibilities

You rewrite exercise 01's raw client with the official @anthropic-ai/sdk, aimed at the same mock. Every responsibility you wrote by hand still exists. Find where each one went.

Why this matters for Hermes Every model call Hermes makes uses this SDK's mechanics: authentication, retries, typed errors, cancellation. Scenario step S4 (model calls) puts that layer below Hermes policy. The six-responsibilities thread continues: the SDK absorbs all six, and the wire does not change.

1 · Nothing changes on the wire

Exercise 02 points the official SDK at exercise 01's mock through one option, baseURL. Start the mock, run the SDK client, and watch the server's terminal. The mock logs the same POST /v1/messages and answers with the same canned fixture. It cannot tell the two clients apart. An SDK does an API's chores. It does not change the API.

The circled numbers below are lesson 0001's six responsibilities: ① endpoint, ② authentication, ③ API version, ④ request and response shape, ⑤ errors, ⑥ cancellation.

2 · Construction is configuration

Exercise 01 scattered the six responsibilities across one function. The SDK gathers the durable ones into an API client: an object that holds connection settings and exposes the API's operations as typed methods. Construction is configuration. Calls are use.

const client = new Anthropic({
  baseURL: "http://localhost:8787", // ① default: ANTHROPIC_BASE_URL, else api.anthropic.com
  apiKey: "mock-key",               // ② default: ANTHROPIC_API_KEY from the environment
  maxRetries: 2,                    // ⑤ the default
  timeout: 600_000,                 // ⑥ the default, in MILLISECONDS
});

Everything set here is a default for the client's whole life. A single call can override the transport through request options: a second argument of per-call transport settings, kept separate from the request body. Params say what you are asking. Options say how this one call behaves on the wire.

await client.messages.create(
  { model, max_tokens, messages },                 // params: the ④ request shape
  { headers: { "x-mock-scenario": "rate-limit" },  // options: this call only
    maxRetries: 0, timeout: 200, signal: controller.signal },
);

Read the call one link at a time.

The declaration of create has three overloads, and the params type decides the return type. Without stream: true the call promises one Message. A signature tells TypeScript what may be called. The implementation does the runtime work. The SDK abstracts chores away from your application code, not away from TypeScript.

Every default above comes from the SDK's own files, not from its docs. A declaration file is a .d.ts file that states a package's types and documented defaults, with no implementation. The constructor's JSDoc in node_modules/@anthropic-ai/sdk/client.d.ts states the environment fallbacks, the 10-minute timeout, and maxRetries: 2. For a generated SDK they are the authoritative description of its surface. The exercise starts there.

3 · Errors and cancellation, measured

Responsibility ⑤ used to be your if (!res.ok) branch. The SDK raises a typed error instead: a failure raised as a distinct class per failure family, carrying structured fields. The hierarchy lives in core/error.d.ts.

// core/error.d.ts (abridged)            // what your catch receives
export declare class APIError {           RateLimitError {
  readonly status: number | undefined;      status: 429,
  readonly type: ErrorType | null;          type: "rate_limit_error",
  readonly requestID: string | null;        requestID: "req_mock_0001",
  readonly headers: Headers | undefined;    headers: { "retry-after": "5", ... },
}                                         }
export declare class RateLimitError
  extends APIError<429, Headers> {}

A 429 does not reach your catch at once, because the SDK retries first. Retry with exponential backoff means re-sending a failed request after waiting longer between attempts. The SDK retries connection errors, 408, 409, 429 and 5xx answers, twice by default, and it obeys the retry-after header. Measured against the mock's scripted 429: three requests in the server log, 10.1 seconds of client silence, then one RateLimitError. With maxRetries: 0 the same failure surfaces in 17 milliseconds.

Responsibility ⑥ has two knobs. A timeout of 200 milliseconds expires inside the mock's 400-millisecond latency. The SDK treats a timeout like a connection error: three attempts, then APIConnectionTimeoutError after about 2.1 seconds.

Cancellation is stopping an in-flight request on purpose. Pass an AbortController's signal in the request options and call abort(). One attempt stops, APIUserAbortError surfaces at once, and the SDK retries nothing.

4 · What moved to compile time, and what did not

In exercise 01 you misspelled messages and learned about it from a 400. The same typo now never reaches a running process.

error TS2769: Object literal may only specify known properties, but 'mesages'
does not exist in type 'MessageCreateParamsNonStreaming'.
Did you mean to write 'messages'?

Remove max_tokens and the check fails again with a missing-property error. Two of the mock's 400 gates moved into tsc. Three things deliberately did not move.

The model id still compiles when misspelled. The declaration reads Model = 'claude-opus-4-8' | … | (string & {}), a union of known ids plus one member that admits any string. New models must keep working against old SDKs, so the catalog stays on the server.

The key's value still passes everywhere. A value like apiKey: "definitely-not-real" satisfies the compiler and the mock alike. Lesson 0002's line between presence and authenticity has not moved.

The response is still trusted, not checked. The SDK attaches its Message type to parsed bytes by assertion, the same pipeline lesson 0001 §3 dissected, now generated instead of hand-written. Nothing at runtime checks that the bytes match the type. Lesson 0005 closes that gap: Hermes validates model-shaped data with Zod at the boundary.

New today. Five ideas are new.

  • An API client holds connection settings once. Every call inherits them.
  • Params and options are separate arguments: what you ask, and how one call behaves.
  • The SDK retries some failures for you and obeys retry-after.
  • Failures arrive as typed error classes with structured fields.
  • Declaration files state a generated SDK's types and defaults. Read them first.

Reprise: the six responsibilities, the base URL, presence against authenticity, and the parse-then-assert pipeline.

5 · The exercise

The commands and the full experiment table live in hermes-sdk-lab/02-model-client-sdk/README.md. The exercise has five steps.

  1. Read the declarations first. Open node_modules/@anthropic-ai/sdk/client.d.ts, find the constructor, and read the documented defaults for apiKey, baseURL, timeout and maxRetries.
  2. Break it before you build it. Write the create call with mesages, run pnpm typecheck, and read the error. Fix it, delete max_tokens, read again, undo.
  3. Send it. Terminal 1 runs pnpm mock, terminal 2 runs pnpm request. On the 200, print the same four things as exercise 01 and diff the two clients' output.
  4. Run the ⑤ and ⑥ experiments: the rate-limit header with and without maxRetries: 0, the 200-millisecond timeout, the 100-millisecond abort. Watch both terminals. Count the requests the mock logs.
  5. Close the loop. For each failure, name the layer that caught it: the compiler, the SDK, or the mock. Then say what only the real API could have caught.
