What the Run Cost

Every trace line records a time, and every reply records its tokens. Can one function turn a trace file into a cost per step that agrees with the job's own total?

Why this matters for Hermes Scenario step S7 (the durable record) gets a second reader that computes cost from it. S6 (budget enforcement) gets its alert placed at a call. S8 (landing the outputs) will link each output to this report. The trace stays the one record of what happened, apart from the workflow graph and the knowledge graph. The win is --cost-report, which agrees with job_ended on all seven recorded runs.

1 · The trace already holds most of the cost

Lab 07's supervisor writes one JSON line per event, and every line carries at, the time in epoch milliseconds. Every reply line carries the provider's token counts. The last line, job_ended, carries the job's totals.

QuestionIn the trace?Where it comes from

Which call crossed 80% of the ceiling?nojob_ended.notes holds the alert as a string, with no call number

A span is one timed step of a run: when it started, when it ended, and what it used. The function costReport reads the trace's events and returns one span per model call and one per tool run. It writes nothing.

New today. Four ideas are new.

  • Trace lines pair into spans that carry time, tokens and dollars.
  • The per-step sums must equal the job's own totals, and a test fails if they differ.
  • A cut-off call's tokens are a remainder, so the report labels them estimated.
  • The 80% alert gets a call number, which the trace's note never held.

2 · Lines pair into spans

The function has a short object path. Import it, pass the events and a price, then check which side of the union came back.

There is one declaration and no overload. A signature tells TypeScript what may be called. The implementation does the runtime work. A record with no job_started line returns ok: false, because it cannot say what ran.

The table stores prices as integer micro-dollars per token. Five dollars per million tokens is 5 micro-dollars per token. Integer sums are exact, so the test can compare totals with ===.

3 · The sums must agree with the record

The report computes its totals from the spans, then compares them with job_ended. A report that disagrees with the record says agrees: false, and --cost-report exits 1.

Two runs stopped inside a call, and no reply line exists for it. The supervisor still booked that call's spend into job_ended, from its own estimate. The report books the remainder to the cut-off call and marks it source: "remainder". A remainder is booked as zero when it would fall below zero, and the totals then miss the record. On these two runs the totals match by construction, so that floor is the only token check.

A remainder has no input and output split, so the report prices it at the output rate. That gives an upper bound. The tight budget's cut-off call shows "$0.003150 at most". That is more than audit-atlas's completed call 2, which cost $0.001600.

A test changes one reply's output count by one token. The sum becomes 218 against the record's 217, and agrees turns false. A record with no job_ended also fails to agree, because nothing confirms the sum.

4 · The pack's share, and the call that crossed 80%

The pack sits in the first turn, and every call resends the transcript. So every call pays for the pack again. The report estimates the pack at one token per four characters, which is the mock's counting rule. 509 characters give about 128 tokens per call.

Lesson 0016 measured the pack by pairing two runs. The grounded run's inputs, 162 and 248, are 129 above the bare run's, 33 and 119. The estimate is one token short. The test allows two. Over two calls the pack used about 256 of the grounded run's 494 tokens.

The alert fires when spend reaches 80% of the ceiling. The tight budget's ceiling is 190 tokens, so the line is 152. Its job_ended note says only "estimated spend passed 80% of 190". The report adds each call's tokens in order and finds the first call whose total reaches the line.

On all seven recordings, the report places an alert exactly where job_ended noted one. The tight budget's placement rests on the estimated remainder, and the report says so. The supervisor checks an estimate while a call runs, so close to the line the two could disagree.
