The Model Gateway

Exercise 04's client imports the SDK, catches its errors, and keeps the job's ledger in one file. Where does the line between the SDK and Hermes go?

Why this matters for Hermes Scenario step S4 (model calls) puts every one behind the ModelGateway. The SDK's mechanics run below it, and Hermes policy sits above it. Failures reach the supervisor as data it can classify. The same interface carries the abort signal S6 (budget limits) needs, and the request id for S7 (the trace). Two threads advance: the six responsibilities move below the line, and lesson 0005's parse lands.

1 · The cost of copying the client

Open exercise 02's client.ts and read it as a supervisor would. One file builds the client, catches three error classes, and reads message.usage into a ledger. Lessons 0008 to 0011 would repeat all of it in every file that wants a model call.

  • A 429 unwinds the caller's stack. Every caller writes the same instanceof chain to survive one.
  • Policy tests need the mock process running, and a stale one has cost three sessions.
  • Code that names Anthropic.Message couples to the provider at every call site.

One seam fixes all three. It changes less than that claim suggests, so read the layers first.

New today. Five ideas are new.

  • A port is an interface the domain owns.
  • An adapter translates calls down, replies up, and exceptions into data.
  • Above the port, every outcome of a call is a value.
  • A fake is a working implementation of the port, running in memory.
  • Provider neutrality is a property of the interface, not a count of adapters.

Reprise: the six responsibilities, typed error classes, the abort signal, safeParse, and narrowing a union on its tag.

2 · The port: an interface the domain owns

You have met this move at the wire. Lesson 0002's base URL swapped the real API for the mock. A port is an interface the caller owns, written in the caller's own words. It swaps implementations at build time instead. One word now carries two meanings.

The wordWhat it namesWhere you met it
port 8787a TCP address, where a process listens for bytesthe mock, since exercise 01
the port in ports and adaptersan interface the domain owns, where implementations plug ingateway.ts, built today

Read the declaration first, as lesson 0003 read the SDK's entry point (05-model-gateway/src/gateway.ts, abridged).

export interface ModelCall  { prompt: string; maxTokens: number }
export interface ModelReply { text: string; stop: StopCause;
                              usage: { inputTokens: number; outputTokens: number };
                              requestId: string | null }

export type GatewayResult =                       // narrow on `ok` — lesson 0005's move
  | { ok: true;  reply: ModelReply }
  | { ok: false; failure: GatewayFailure };

export interface ModelGateway {
  complete(call: ModelCall, options?: { signal?: AbortSignal }): Promise<GatewayResult>;
}
SyntaxMeaningAt runtime?
interface ModelGatewaya contract in the domain's wordsnothing. TypeScript erases every interface
implements ModelGatewaya build-time claim on a classnothing of the claim. The class survives
gateway.complete(call)a call through the port's signaturewhichever implementation the wiring chose
options?.signalthe supervisor's kill switch crossesa real AbortSignal, owned by the web platform

A signature tells TypeScript what may be called. The implementation does the runtime work. One signature has two implementations today, and the domain cannot tell which one it holds.

Dependency inversion names the arrow that just turned around. The concrete code imports the domain's interface, and the domain imports no concrete class. One command checks it. Run grep -r "@anthropic-ai/sdk" src/ and you get the adapter and the wiring.

// Part A — the proof arm                  // Part B1 — the refusal arm
{                                          {
  ok: true,                                  ok: false,
  reply: {                                   failure: {
    text: "Hello from the mock. These bytes…",              kind: "throttled",
    stop: "completed",                         retryAfterMs: 5000,
    usage: { inputTokens: 11,                },
             outputTokens: 42 },           }
    requestId: "req_mock_0001",            // the wire said `retry-after: 5` (seconds).
  },                                       // the port speaks milliseconds: translation,
}                                          // not passthrough

Read what the vocabulary did. end_turn became completed, and input_tokens became inputTokens. A RateLimitError became { kind: "throttled" }. No provider spelling survives above the line.

3 · The adapter: three translations, no new bytes

During Part A the mock's terminal prints the exchange exercise 02 produced.

POST /v1/messages  (req_mock_0001)
x-api-key: … · anthropic-version: 2023-06-01 · content-type: application/json
{ "model": "claude-opus-4-8", "max_tokens": 100, "messages": [ … ] }

HTTP/1.1 200 OK · request-id: req_mock_0001 · stop_reason=end_turn input_tokens=11

The port added nothing to it. No header, no envelope, no extra hop. The network cannot see build-time architecture. An adapter is a class that implements a port by translating one concrete dependency into the port's words. This one translates three things.

  1. The call goes down. ModelCall becomes the SDK's params object, and the model id arrives as constructor configuration.
  2. The reply comes up through the boundary parse. WireReplySchema.safeParse checks the fields ModelReply consumes.
  3. The failures come up as data. The adapter writes exercise 02's instanceof chain one last time, and returns a GatewayFailure value.

SDK error classes are runtime values, which is why instanceof works on them. The port's interfaces are erased. The adapter rethrows any error it cannot classify, because a bug must stay loud.

B1 throttled → { outcome: 'retry_later', tokensSpent: 0,
                 notes: ['provider asked for 5000 ms of backoff'] }
B2 aborted   → { outcome: 'gave_up',     tokensSpent: 0, notes: ['aborted by the operator'] }
B3 malformed → { outcome: 'gave_up',     tokensSpent: 0, notes: [
                 'reply refused at the boundary',
                 'stop_reason: [invalid_value] Invalid option: expected one of …',
                 'usage.output_tokens: [invalid_type] Invalid input: expected number, received string' ] }

B3 sends exercise 04's drifted bytes. They once produced a ledger of "1142" against a real spend of 53. Here they never reach a ledger. Your lesson 0005 recall made the argument: a plausible silent error is more dangerous than a conspicuous false alarm.

4 · The fake, and the provider decision

A fake is a working implementation of a port that answers from a script. FakeModelGateway is the port's second implementation, and a test artifact rather than a second provider.

the mock serverFakeModelGateway
doubles the API atthe wire: real HTTP on port 8787the port: a method call, in memory
exercisestransport, the six responsibilities, the parsethe supervisor's decisions alone
costs, measured~400 ms per call, latency on purpose0.6 ms for two calls, mock stopped

Part C stops the mock and runs the same supervisor against the fake. The landed report matches Part A's, except that request reads (none). The scripted throttle drives the retry_later branch B1 drove over the wire.

One question has stood open since session 1. Decided: a provider-neutral port with exactly one live adapter. The port's words name text, a stop cause, two usage numbers and a failure kind, so neutrality cost nothing. No benchmark asks for a second live adapter, and MISSION rules out speculative work. Provider choice arrives later, above the port, as a routing decision.

A port built against one provider can grow that provider's shape. The fake answers that risk from day one, and proves nothing about a real second provider.

5 · The exercise

Commands and the measured table live in 05-model-gateway/README.md. The arc:

  1. Read gateway.ts, supervisor.ts, then anthropic-gateway.ts. At each import, say which side of the port you are on.

  1. Define port and adapter in one sentence each. Say which one survives compilation, and what enforces the one that does not.
  2. Trace a 429 from the wire to the supervisor. Name what the SDK hands the adapter, and what the adapter hands the port.

If you keep only five sentences from Phase 1's opening, keep these. A port is an interface the domain owns, and the domain and its adapters both depend on it. The adapter translates calls down, replies up through the parse, and exceptions into failure data. Above the port every outcome is a value the supervisor classifies. A fake implements the port in memory, so policy is testable with no server.
