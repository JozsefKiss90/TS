Evidence With Provenance

Lesson 0013's server answered with a title and a status. What must an answer carry before Hermes may believe it?

Why this matters for Hermes This lesson builds toward scenario step S2 (evidence assembled), where every Context Pack item carries provenance. Today the evidence schema exists, the server returns it, and a malformed answer is refused before a client sees it. The boundary rule gains a sixth surface: a file that another language wrote. Provenance describes what Hermes knows. What Hermes did stays in the trace of lesson 0011, a separate record.

1 · Three questions an answer must carry

A node from exercise 09 has an id, a title and a status. Nothing in it says who stands behind the claim, how it was produced, or how far to trust it. A Context Pack cannot admit such a node.

Provenance is the record of a claim's origin: who stands behind it, which activity produced it, and what it was made from. W3C PROV-DM is the published standard for that record. It uses three nouns. An entity is a thing with fixed aspects. An activity is something that occurs over time and acts on entities. An agent bears responsibility for an entity or an activity.

Two of those words already mean something else here.

TermMeaning in this courseMeaning in PROV-DM or dev_graph
agenta loop that acts on a model's decisions (Phases 5 and 6)PROV-DM: whoever is responsible for an entity. The schema says sources instead.
evidenceone claim packaged with its provenance (this lesson)dev_graph: a list of the kinds of backing a node has, such as code or ADR

The schema keeps three PROV-DM relations, each as one field.

PROV-DM relationFieldQuestion answered
wasAttributedTosourceswho stands behind this claim?
wasGeneratedBygeneratedBywhich activity produced it, and when?
wasDerivedFromderivedFromwhich earlier record was it made from?

A derivation is the link from a record to the earlier record it was made from. An item is derived from one export row, and the row from a markdown note.

New today. Five ideas are new.

  • A claim without provenance cannot be admitted, and provenance answers three questions.
  • Confidence is a label from a closed list with a promotion rule, never a number.
  • An output schema travels and guards the answer, as the input schema guards the arguments.
  • The knowledge graph gets a port, and the export's spellings stop at the adapter.
  • A bundle of items carries provenance of its own.

Reprise: the port (lesson 0006), refinements (lesson 0007), the boundary parse (lesson 0005), tools and resources (lesson 0013).

2 · The schema, as declaration and as value

An evidence item is one claim from the knowledge graph, packaged with its provenance.

// src/evidence.ts, abridged                  // graph://evidence/MOD-001, measured
export const ProvenanceSchema = z.object({     {
  sources: z.array(SourceSchema).min(1),         "id": "MOD-001",
  generatedBy: z.object({                        "claim": "ModelGateway port is implemented (module).",
    activity: ActivitySchema,                    "provenance": {
    at: z.iso.datetime(),                          "sources": [
  }),                                                { "kind": "code", "ref": "07-tool-loop/src/gateway.ts" },
  derivedFrom: z.array(z.string()).default([]),      { "kind": "adr",  "ref": "ADR provider-neutral port …" }
  confidence: ConfidenceSchema,                    ],
}).refine(                                         "generatedBy": { "activity": "graph-export",
  (p) => p.confidence !== "confirmed"                              "at": "2026-09-09T18:00:00Z" },
        || p.sources.length >= 2,                "derivedFrom": ["dev-graph-2026-09-09#MOD-001"],
  { message: "confirmed needs at least two sources",   "confidence": "confirmed"
    path: ["confidence"] });                     }
                                               }
export const EvidenceItemSchema = z.object({
  id: z.string().min(1),
  claim: z.string().min(1),
  provenance: ProvenanceSchema,
});

A source is a kind and a reference a person can open. The seven kinds come from dev_graph's list of backing kinds. An item needs at least one source.

Confidence is a label from a closed list that says how well a claim is supported. It is not a probability. The five labels are dev_graph's, and each has a rule for moving to the next.

LabelWhat it saysHow a claim gets there
confirmedtwo independent sources agreea second source corroborates
single-sourceone source states it directlya source document is found
inferredit follows from confirmed factsa derivation is written down
speculativea guess, or a contradiction was foundany label drops here when sources disagree
experimentala hypothesis under testan experiment starts

The first row is a cross-field rule, so it is a refinement. A confirmed item must carry two sources. Measured: an export row marked confirmed with one source stops the server at wiring.

A query's answer is a bundle: the items, plus who assembled them, from which snapshot, and when. PROV-DM lets a set of provenance descriptions be an entity itself, so provenance can have provenance.

3 · The port, the adapter, and the guard on the way out

The loop reaches the graph through a port. The path is short: import the adapter, construct it over the export, hold it as a KnowledgeGraph, and call search. A miss is an empty bundle, never a throw, because "not in the graph" is an answer the loop must read.

// src/graph-port.ts                        // src/evidence.ts, the bundle
export interface KnowledgeGraph {            export const EvidenceBundleSchema = z.object({
  search(query: string, limit: number):        query: z.string(),
    Promise<EvidenceBundle>;                   assembledAt: z.iso.datetime(),
  node(id: string):                            assembledBy: z.object({
    Promise<EvidenceItem | undefined>;           adapter: z.string().min(1),
  all(): Promise<EvidenceItem[]>;                snapshot: z.string().min(1),
}                                              }),
                                               items: z.array(EvidenceItemSchema),
                                             });

The adapter reads a JSON file the Python side wrote, a stand-in for dev_graph's own export. Bytes from another program are untrusted, so the adapter parses the file against a schema written in dev_graph's spellings: canonical_id, source_paths, related_decisions. Measured: confidence: "probably" is refused at nodes[0].confidence.

The adapter translates each row once. Code paths and decision records become sources. The export time becomes the generating activity. The snapshot name and canonical id become the derivation. The confidence label crosses untranslated, because Hermes adopts dev_graph's scale.

The server registers the tool with one new property.

PieceSyntaxMeaningWhat exists at runtime
outputSchema: EvidenceBundleSchemaconfig propertythe answer's shapeconverted to JSON Schema once, served on every list
structuredContent: bundlefield of the returned value the answer, as dataparsed against the output schema after the handler returns

A signature tells TypeScript what may be called, and the implementation does the runtime work. The SDK abstracts chores away from your application code, not away from TypeScript. The new chore: the parse on the way out.

The malformed answer never reached the client as data. It came back in-band, the channel a bad argument used in lesson 0013, so a model can read the refusal.

One rule does not travel. The tools/list reply carries the seven kinds and minItems: 1, and no two-sources rule, because JSON Schema cannot express a refinement. The rule guards the server's boundary only. A client that wants it parses with the Zod schema itself, in lesson 0015.

If you keep only four sentences from this lesson, keep these. Provenance answers who stands behind a claim, which activity produced it, and what it was made from. Confidence is a label from a closed list with a promotion rule, not a number. The output schema travels and guards the answer after the handler runs, but a refinement guards only the boundary. The adapter parses the export in dev_graph's words and translates once, so the port speaks only Hermes's.
