The Spec Decides the Graph

Lab 12 runs every job under one graph of 13 nodes and 26 edges. Which of them can one job's TaskSpec remove before the job starts?

Why this matters for Hermes Scenario step S3 (dispatch under the graph) now starts from a graph built for one job. In S5 (the loop iterates), a job that holds nothing has no approval wait. S2 (evidence before dispatch) becomes a missing edge. The workflow graph stays apart from the knowledge graph and the trace. The win is a hold on the audit's graph, refused before anyone is asked.

1 · One graph holds every job's paths

Lab 12's graph file holds every path that any spec could need. The audit holds no tool for approval, but its run still has an edge from gating to awaiting_approval. That edge stays closed only because gateToolCall never answers hold for this spec. If the gate code changed, the graph would allow the wait.

A job graph is the workflow graph one job runs under: the full graph without the nodes and edges its TaskSpec makes unreachable. The function graphForSpec builds it before the job starts. The rule then lives in a value you can read, not only in the gate's code.

A Hermes OS design note draws awaiting_approval only on paths that mutate. Its --no-writeback audit skips that state. Lab 07's spec has no writeback flag, so the audit that may change nothing is a spec with an empty approvalRequired.

New today. Four ideas are new.

  • A job's spec removes nodes and edges from the graph before the job starts.
  • A missing edge refuses a move that only the gate code refused before.
  • A recorded trace shows which job graph its run stayed inside.
  • The decision on LangGraph.js is written down with its evidence.

Reprise: the TaskSpec (0007), the gate (0010), the Context Pack (0016), the strict graph and the walker (0017), the refusal (0018), the port (0020).

3 · The graph refuses what the spec ruled out

The function dispatch feeds one spec value to both sides. It builds the job graph from the spec, then passes the same spec to startJob. Dispatched this way, the audit lands at 2 calls and 80 tokens, as it did on the full graph.

The tests then hand a run a spec other than the one its graph came from. That stands in for a gate that disagrees with its own spec. The graph refuses the move before any handler acts on it.

RunResultCost before the refusal
a held spec on the audit's job graphno_edge, gating to awaiting_approval, step 41 model call, 4 trace lines, last checkpoint at gating
no pack on the evidence job's graphno_edge, started to calling, step 10 model calls, 1 trace line

Two engines can run a job graph, and both refuse both moves. An engine is the code that runs the graph. In pnpm job e it is lab 12's interpreter. In pnpm test it is LangGraph.js, through lesson 0020's swap. The job graph holds the rule, so the engine does not matter.

The trace shows which job graph a run stayed inside. Lab 12's parked audit wrote nine lines under a held spec. The walker finds them legal and complete on that spec's job graph. On the audit's job graph it refuses line 5: no edge gating > awaiting_approval. All seven recorded traces in the repo walk legal and complete on their own spec's job graph.

4 · The decision on LangGraph.js

An architecture decision record is a short file that records one design decision, its options, its evidence, and when to revisit it. The course's first is docs/adr/0001-skip-langgraph-js-keep-the-port.md.

OptionWhat it meansWhat lessons 0018 to 0021 measured
Adoptthe framework keeps the run's record and its resumetwo records say a job waits, the paused node reruns, and Hermes ADR-0018 keeps job truth in Hermes's own files
Wrapthe framework runs behind runGraphit took over traversal only: 66 lines of loop, replaced by 157 lines and two packages that bring 19 more
Skiplab 12's interpreter runs the graphresume from a checkpoint, a verdict from another process, and job graphs all work without the framework

The record decides skip, and it keeps the port. The signature of runGraph stays the place where an engine plugs in. Lab 13's test swap can measure a later candidate with one new file. The record names when to revisit: a store shared by several workers, or progress streamed to a client.
