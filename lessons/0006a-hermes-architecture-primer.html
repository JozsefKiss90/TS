What Counts as Policy

Lesson 0006 put Hermes policy above the port and the SDK below it. Which parts of exercise 05 are policy, and which only look like it?

Why this matters for Hermes Scenario step S4 (model calls) says they cross the port, and policy sits above it. You cannot place a rule correctly until you can say what a rule is. This supplement defines the word and labels what exercise 05 contains. It ships no code.

1 · The definition

Lesson 0006 uses the word policy in almost every section. A Hermes policy is a rule. It turns checked facts into an action Hermes may take, or into a final outcome.

The rule is deterministic, so the same facts always give the same decision. Zod checks the facts at run time, or the port's types guarantee them at build time. The output is always an action Hermes may take, or a state the job ends in. It is never whatever an exception happened to unwind to.

Four other kinds of work look like policy. None of them is. A fifth, the wire protocol, sits below all four and decides nothing at all.

The workWhat it doesIn exercise 05Policy?
the port Names the facts allowed to cross it. gateway.ts: ModelCall, ModelReply, GatewayResult No. It decides nothing. It says what decisions can be about.
wiring Builds the objects and hands them to the code that uses them. main.ts: new AnthropicModelGateway(client, MODEL) No. It settles which object exists. It says nothing about what a result means.
adaptation Translates between Hermes words and provider words, both ways. end_turn becomes completed. Five seconds becomes 5000 ms. No. Translation keeps the meaning and chooses nothing.
SDK mechanics Sends the request, retries it, times it out, throws typed errors. The SDK obeys retry-after twice, then throws RateLimitError No. It runs an operation and holds no view about the job.
wire protocol Carries the bytes. POST /v1/messages to the mock on port 8787 No. Every design above it leaves the bytes unchanged.

Exercise 05 holds two policies. A throttled call means the job waits and runs later. A bad reply means the job stops and counts zero tokens. Each turns a checked fact into a job outcome. Both live in supervisor.ts and could live nowhere else.

"Above" and "below" describe imports and duties. Code above the port imports only gateway.ts and uses Hermes words. Code below the port implements gateway.ts, and must translate provider words before they cross. The pair does not describe secrecy, because nothing is hidden. It does not describe folders, because every file sits in the same src/. It does not describe the call stack, where the supervisor waits below the adapter.

2 · Wiring is not routing

Lesson 0006 says that routing is policy, decided above the port. That sentence is easy to over-read. In exercise 05, main.ts contains this:

const MODEL = "claude-opus-4-8";
return new AnthropicModelGateway(client, MODEL);

main.ts is the composition root. It is the one file that knows the concrete classes and bolts them together. The model name is a constant, and nothing picks it at run time.

The injection still does real work. The adapter cannot hardcode a model, so whoever builds the adapter chooses. That places the decision point above the port. It does not create a routing policy, which would be a rule that picks a model per task from that task's needs. No such rule exists here, and no roadmap row schedules one.

Reserved is not implemented. Lesson 0006 reserves the model choice for policy. It does not yet implement a rule that makes the choice.

7 · Keep these five sentences

If you keep only five sentences, keep these. A Hermes policy turns checked facts into a permitted action or a final outcome. Wiring builds objects and decides nothing. The adapter translates words and decides nothing. The supervisor decides what a result means for the job, and nothing else does.
