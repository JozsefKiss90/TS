Run the Raw Request, Against a Mock

You send lesson 0001's raw request against a local mock. Then you break it six ways, one responsibility at a time.

Why this matters for Hermes Hermes is tested against fakes and recorded fixtures before it makes a paid API call. This lesson builds the first such stand-in: a local server that speaks the Messages API's rules with no model behind it. Scenario step S4 (model calls) sends this same request from inside Hermes. The six-responsibilities thread continues here: each break in the lab makes one responsibility fail in front of you.

1 · The lab you just gained

Three configuration ideas carry the whole lab.

pnpm-lock.yaml is a lockfile: the record of the exact version every dependency resolved to, transitive dependencies included. package.json only states ranges. The range "typescript": "^5.7.0" accepts any 5.x from 5.7 up, and the lockfile records that the install resolved it to 5.9.3. Commit the lockfile, and every later install reproduces the identical tree.

The line "type": "module" switches the package to ES modules: JavaScript's standard module system, import and export with fixed, analyzable meaning. Node's older CommonJS system resolves require calls at runtime. The tsconfig option module: "nodenext" makes TypeScript resolve imports the way Node will. The compiler and the runtime then agree about every import.

The shared tsconfig.base.json turns on strict mode: the TypeScript compiler flags that decide what a compile-time claim may hide. Each line tightens one kind of claim.

tsconfig lineWhat it refuses to let a claim hide
strict: truethe umbrella flag. No implicit any, and null and undefined become real types your code must handle.
noUncheckedIndexedAccessan index can miss at runtime, so content[0] gains undefined in its type. You meet this when you print the first content block.
exactOptionalPropertyTypesan omitted property and a property set to undefined are different things. JSON on the wire has no undefined, so the types keep them apart.
verbatimModuleSyntaxa type-only import must say import type, because the type will not exist at runtime. Lesson 0001 named this fact type erasure.
noEmit: truenothing. tsx runs the .ts files directly, and tsc only checks them. Types are erased either way.

2 · A test double for the wire

src/mock-server.ts is a test double: a stand-in that answers the same calls as a real dependency, so the code under test cannot tell the difference. This double stands in for the Messages API. It enforces the checks lesson 0001 circled, and it returns either a canned Message with the real response shape or a real error envelope. The circled numbers below are lesson 0001's six responsibilities: ① endpoint, ② authentication, ③ API version, ④ request and response shape, ⑤ errors, ⑥ cancellation.

Here is one full exchange, captured against the running mock. The request carries responsibilities ① to ④ as bytes on the wire.

POST /v1/messages HTTP/1.1                     ① the endpoint
host: localhost:8787
content-type: application/json
x-api-key: any-value-passes                    ② checked for presence only
anthropic-version: 2023-06-01                  ③ pins one revision of the rules

{"model":"claude-opus-4-8","max_tokens":1024,  ④ the request shape
 "messages":[{"role":"user","content":"What is an SDK?"}]}

HTTP/1.1 200 OK                                after ~400 ms of simulated latency
content-type: application/json
request-id: req_mock_0001

{
  "id": "msg_mock_0001",
  "type": "message",
  "role": "assistant",
  "model": "claude-opus-4-8",                  the model you sent, echoed back
  "content": [{ "type": "text", "text": "Hello from the mock. ..." }],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": { "input_tokens": 12, "output_tokens": 42, ... }
}

A failed gate answers with the same envelope shape the real API uses. This is what your client reads when the key header is missing.

HTTP/1.1 401 Unauthorized
request-id: req_mock_0002

{ "type": "error",
  "error": { "type": "authentication_error",
             "message": "x-api-key header is required" },
  "request_id": "req_mock_0002" }

The double checks presence, not truth. Any value in x-api-key passes, because only Anthropic's servers know which keys are real. A double can enforce the shape of the rules. It can never verify the truths behind them: real keys, real rate limits, the real model catalog.

The request above reached localhost:8787 because the base URL is the host part of the request's address, treated as configuration the caller may change. The API fixes the path /v1/messages, never the host. Your client reads ANTHROPIC_BASE_URL and falls back to localhost:8787. The official SDK exposes the same option as baseURL. Exercise 02 aims the real @anthropic-ai/sdk at this same mock through it, with no change to SDK code.

New today. Five ideas are new.

  • A test double enforces shape, never the truths behind the shape.
  • The base URL turns the request's destination into configuration.
  • A lockfile records what an install resolved.
  • Compiler configuration decides what a compile-time claim may hide.
  • Failures arrive as an HTTP status plus a JSON error envelope.

3 · The exercise

The full commands live in hermes-sdk-lab/01-raw-http/README.md. The exercise has five steps.

  1. Install the toolchain: pnpm install at the lab root. Then find typescript in pnpm-lock.yaml. That is §1's range, resolved and recorded.
  2. Start the mock in a first terminal: pnpm mock inside 01-raw-http/.
  3. Write the request: fill in src/client.ts from memory. The six responsibilities are the checklist, and the mock's errors are the feedback. Run pnpm request in a second terminal until you see a 200 with stop_reason, the text block, and usage.
  4. Break the request six ways. Change one thing at a time. Watch both terminals on every run.
BreakWhat you observe
Delete the x-api-key header401 authentication_error. Responsibility ② is a header the wire demands.
Delete the anthropic-version header400 invalid_request_error. Responsibility ③ pins which revision of the rules you speak.
Delete max_tokens from the bodya 400 naming the field (④). Nothing before the server caught it.
Misspell messages in the bodya 400 at runtime. The SDK's types caught this same typo at compile time in lesson 0001.
Add the header x-mock-scenario: rate-limita 429 with a retry-after header, the input a ⑤ retry policy reads.
setTimeout(() => controller.abort(), 100)an AbortError in the client, and the mock logs an abort mid-flight (⑥).
  1. Run pnpm typecheck. Count which of the six failures TypeScript could have caught. Almost none, because you built the body untyped. Exercise 02 shows which ones the SDK moves to compile time.
