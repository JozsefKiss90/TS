# Roadmap — Agentic Engineering with TypeScript

The course builds the **Hermes Spec-to-Evidence Loop** — a bounded, typed, observable single-agent loop (validated TaskSpec → bounded planning → Graph RAG evidence → approved tool execution → evaluation → durable trace) that becomes the control plane of Hermes OS. Guiding principle: *put probabilistic reasoning inside a deterministic, typed, observable control system.* Full rationale: [MISSION.md](MISSION.md).

## How to read this file

- **This is a plan, not a syllabus.** Lessons are authored one at a time, feedback-first (house rule: never generate a large course in advance). Shipped entries are history; the next lesson is firm; everything further is provisional — titles, counts, and order get resequenced as feedback lands. The *why* behind every change is recorded in [NOTES.md](NOTES.md) dated updates.
- **Status:** ✅ shipped · ▶ next up · ○ planned (provisional scope) · ⛔ gated (entry criterion unmet)
- **Numbering:** `NNNN` ids are firm through the next lesson; later ids are placeholders and may shift. Phase 2+ lessons get ids when their phase opens.
- One lesson ≈ one session (~45–60 min). Every lesson ships three things: the HTML lesson, its glossary-wiki cluster (`wiki/terms/` + lesson map), and at least one Mermaid diagram. Lab exercises live in `hermes-sdk-lab/` (pnpm workspace, **mock-first** — live API calls only after the cost/auth route is confirmed).
- Standing separations that shape the whole sequence: the three graphs never merge (**knowledge** = what Hermes knows · **workflow** = what it may do · **trace** = what it did); model-client SDK before Agent SDK; single-agent before multi-agent; raw HTTP before SDK.
- **Graph form & governance:** this plan as Mermaid module graphs: [wiki/course/course-module-graph.md](wiki/course/course-module-graph.md) — kept in sync when a status flips. What a lesson must be: [CLAUDE.md](CLAUDE.md) (the constitution). What the course means — terminal skills and the Hermes OS integration scenario (steps S1–S9) every lesson anchors to: [wiki/course/](wiki/course/COURSE.md).

## Phase 3 — The workflow graph — *complete ✅ (opened 2026-10-06; 0021 shipped 2026-10-30); Phase 2 exit met 2026-09-30; lessons defined 2026-10-05*

**Goal:** the loop's control flow becomes an explicit state graph — what Hermes *may* do, encoded as data.
**Framework decision:** LangGraph.js is the candidate (persistence, interruption); evaluated, not assumed — and never learned alongside an alternative in the same phase.
**Sequence rule, applied:** the hand-written graph comes before the framework, the way raw HTTP came before the SDK in Phase 0. Lessons 0017–0019 use no framework. Lesson 0020 meets LangGraph.js the way lesson 0003 met the client SDK: as a layer whose absorbed responsibilities you can already name because you wrote each one.
**Starting point:** lab 11's supervisor already has six outcomes (`landed`, `retry_later`, `gave_up`, `over_budget`, `out_of_time`, `no_evidence`) and an eight-kind trace, but its control flow is `if` statements in `supervisor.ts`. The Hermes record has no accepted state set — its job lifecycle is a *proposed clarification* ([hermes-job-control-plane.md](docs/hermes_os/architecture/hermes-job-control-plane.md) §4). The lab's graph is built against that proposal and labeled so (Article III.9).
**Guardrail:** a checkpoint is workflow-side state kept so a job can continue; the trace is what happened. Neither becomes the other, and the graph holds no claims and no events.
**Prerequisite (before 0020):** pin an exact LangGraph.js version and verify its checkpoint and interrupt surfaces against current docs in-session (Article IV.1–2).

## Phase 4 — Reliability and evaluation — *open since 2026-10-30; 4 of 6 shipped*

**Goal:** make claims about the loop with evidence: traces, costs, golden tasks, regressions.
**Sequence rule, applied:** hand-written before the library, as in Phases 0 and 3. Lesson 0022 computes spans and cost from the trace file with no telemetry package; lesson 0023 meets OpenTelemetry JS as a layer whose work you already did, and ends in an adopt / wrap / skip record like ADR 0001. Outputs land (0024) before anything scores them (0025), because a grader needs an addressable artifact to read.
**Starting point:** lab 12's trace already records everything a cost report needs: every event carries `at` (epoch ms), every `reply` carries `inputTokens` / `outputTokens` and `requestId`, `job_ended` carries the totals, and `evidence_used` carries the pack's size. The S6 alert at 80% of the ceiling fires (lab 07 `supervisor.ts`, lab 12 `handlers.ts`), but only as a string in `job_ended.notes`, with no time and no step. What is missing: per-step attribution, dollars, any landed output (S8 has no code), and any score (S9 is the 0012 test suite, which checks behavior but grades nothing).
**Guardrails:**
- The JSON Lines trace stays the one record of what happened. Spans, cost reports and OpenTelemetry exports are computed from it or emitted beside it as views, and a test proves they agree with it. None becomes a second record.
- A grader is never the thing it grades (Hermes ADR-0009, *accepted*). Graders are names in the golden-task file and functions in code, the shape lab 12's guards already have.
- A benchmark run on fakes measures the harness, not the model. Phase 4 runs on fakes only (decided 2026-10-30, below), so no Phase 4 number is a claim about the model, and none can open the Phase 6 gate.

**Prerequisites:**
- *Before 0023 (met 2026-10-30):* `@opentelemetry/*` versions pinned exact (api 1.9.1, sdk-trace 2.12.0, resources 2.12.0, otlp-transformer 0.223.0); the GenAI conventions, now in `open-telemetry/semantic-conventions-genai`, are status Development throughout, and the lesson says so once, in its status table and the convention note.
- *Before 0025 (met 2026-10-30):* vet a primary source for agent-harness evaluation (golden tasks, repeated trials, replayable fixtures). RESOURCES gap, flagged since session 1. Vetted: Anthropic's [Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (2026-01-09; task, trial, grader, pass@k, pass^k), the τ-bench paper (arXiv 2406.12045; pass^k) and Anthropic's success-criteria docs page; see RESOURCES. Candidates listed at the time: the τ-bench paper (pass^k over repeated trials), Anthropic's published guidance on agent evals, and the Hermes OS harness record (`docs/harness-wiring.md` in the `hermes-os` repo; the ≥30-golden-question threshold in [hermes-job-control-plane.md](docs/hermes_os/architecture/hermes-job-control-plane.md), component 10).
- *Run source, decided 2026-10-30 (user): no budget; a seeded fake model.* The fake draws its replies from a fixed set of recorded variants with a seed, so a trial's variation is chosen, and any trial is reproducible from its seed. Every number in 0026 and 0027 is labelled a harness measurement. Live runs stay out of Phase 4.

## Phase 6 — Multi-agent — *⛔ gated on benchmark evidence*

**Entry criterion (hard):** a Phase 4 benchmark showing a mission-relevant task where the single-agent loop's ceiling — not its tuning — is the blocker. No evidence, no phase. MISSION lists premature multi-agent demos as explicitly out of scope.
**Consequence of the 2026-10-30 run-source decision:** Phase 4 runs on a seeded fake only, and a fake's ceiling is whatever its variants were written to do. The criterion stays unmet until a live benchmark run exists, which needs a budget.

- **When Two Agents Beat One** — coordination cost accounted honestly against the measured single-agent baseline.
- **Orchestration, As Much As the Evidence Buys** — only the patterns the benchmark justifies; the loop remains the unit of control.

**Exit criteria:** multi-agent coordination that beats the single-agent baseline on the benchmark that gated it — or a documented decision that one agent is enough.
