Lesson 0006 leaned on the word "policy" in nearly every section; here is the definition it deserves:

A Hermes policy is a deterministic rule that converts validated facts — about a task, the loop's state, or an external result — into a permitted next action or a terminal outcome. Deterministic: same facts, same decision, every time. Validated facts: nothing crosses into a policy rule without a runtime check (lesson 0005) or a compile-time contract (lesson 0006). Permitted: the output is always an action Hermes is allowed to take, or a terminal state — never "whatever the exception unwound to."

The word earns its keep only if it excludes things. Four neighbours get mistaken for policy, plus the wire beneath them all — learn to tell the five apart and lesson 0006's "mechanics below, policy above" becomes a precise sentence instead of a slogan.

After — the proposed profile (about 330 words)

2 · What "policy" means here

Lesson 0006 uses the word policy in almost every section. This is what it means.

A policy is a rule that turns checked facts into a decision. The facts describe the task, the loop, or a result that came back. The decision is an action Hermes may take, or a final outcome. The same facts always give the same decision. A fact counts as checked if Zod parsed it at run time, or if the port's types guarantee it at build time.

The word is only useful if it rules things out. Four other kinds of work look like policy but are not. The wire protocol sits underneath all four. Learn to tell the five apart.

The workWhat it doesExample in exercise 05Policy?
port contract Names the facts that may cross the seam. It decides nothing. gateway.ts: ModelCall, ModelReply, GatewayResult No. It says what decisions can be about.
wiring Builds the objects and hands them to the code that uses them. main.ts: new AnthropicModelGateway(client, MODEL) No. Choosing which object exists is not deciding what a result means.
adaptation Translates between Hermes words and provider words, both ways. anthropic-gateway.ts: end_turn becomes completed; 5 s becomes 5000 ms No. Translation keeps the meaning and chooses nothing.
SDK mechanics Sends the request, retries it, times it out, and throws typed errors. The SDK obeys retry-after twice, then throws RateLimitError No. It runs an operation. It holds no view about the job.
wire protocol Carries the bytes. POST /v1/messages to the mock on port 8787 No. The wire cannot see the architecture above it.

Exercise 05 holds two policies. First: a throttled call means the job waits and runs later. Second: a bad reply means the job stops and counts zero tokens. Each one turns a checked fact into a job outcome. Both live in supervisor.ts.

"Above" and "below" describe imports and duties. They describe nothing else. Code above the port imports only gateway.ts, and uses Hermes words only. Code below the port implements gateway.ts. It may use provider words, but it must translate them before they cross. The two words do not describe security, because nothing is hidden. They do not describe folders, because every file sits in the same src/. They do not describe the call stack, because at run time the supervisor waits below the adapter.
